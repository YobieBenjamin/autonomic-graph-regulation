The YB-0035 experiment itself holds up, but neither blog is ready to post as written. The plain-English one needs substantive rewording; the technical one needs a set of targeted fixes.

## Summary

**The YB-0035 code and data check out.**
- **No leakage:** I found no look-ahead or leakage in the features, normalization, thresholds, bootstrap, first-crossing timing, fixed compute cost or the never-answered sensitivity analysis.
- **Seed shifts:** the seed 2–6 shift goes the right way, and seed 7 is packed with no shift and one reading per token (I re-checked every array).
- **Pre-registration timing:**
  - The analysis code has not changed since commit b6c795b (08:22:36 PDT).
  - The first seed-7 episode started at 08:26:49 PDT.
  - The recording times match the chain log.
- **Numbers:** all data fingerprints match. I recomputed the judge (11/40) and length (9/40) results independently.
- **Slow hardware doesn't explain the win:** a judge with no deadline at all still catches only 13/40.

**The problems are in how the result is interpreted.**

- **Plain-English blog: not fit to publish.**
  - Its framing that watching the words can't tell you when to worry is contradicted by the project's own YB-0031 results (see B1).
  - It calls these "confident" wrong answers and says the warnings come "earlier"; neither is supported by the data.
  - It says each test set is "brand new and used once", which is false for seeds 5 and 6.
  - It presents a false-alarm limit set using the test answers as if it were a real-world guarantee.
- **Technical blog: fixable.** The audit counts are wrong, it claims a win over a baseline that was never run, it overstates robustness, and the realignment check isn't fully disclosed.
